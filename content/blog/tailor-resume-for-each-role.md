Tailoring a resume should change the emphasis, not the facts.

The fastest way to make a resume feel specific is to move the right proof closer to the top. The slowest way is to rewrite every sentence from scratch and accidentally blur the story.

## Start with the next job, not the last job

Read the job description and write down the three things the hiring team appears to value most.

For a product engineering role, that might be shipping customer-facing features, owning ambiguous product decisions, and moving quickly in a small team. For a go-to-market role, it might be pipeline, customer trust, and repeatable process.

Your resume version should make those strengths easy to find.

## Keep one canonical source

Maintain a base Tiny CV markdown file with the facts you trust: roles, dates, companies, links, metrics, and projects.

When you create a role-specific version, edit from that base instead of starting from a blank page. This keeps the tailoring grounded and makes it less likely that a metric, title, or date drifts between versions.

## Change the summary first

The summary is where tailoring has the most leverage.

Use it to connect your strongest evidence to the role in front of you. Do not stuff it with keywords. A good summary should answer one question: why should this person keep reading?

## Promote matching proof

After the summary, adjust the order and detail level of the bullets.

If a target role values APIs, move API work into the first or second bullet for the relevant role. If it values design taste, bring selected work and product craft forward. If it values revenue, make customer, pipeline, or pricing proof easier to scan.

## Cut what does not help

Tailoring is as much deletion as rewriting.

Older roles, generic responsibilities, and low-signal projects can move into Additional Experience or disappear from that version. One page forces the resume to make decisions, which is exactly why the format works.

## Use agents carefully

Agents are useful for reshaping bullets, checking whether a resume matches a target role, and finding weak sections.

They should not invent metrics, employers, degrees, or impact. The right workflow is simple: give the agent the canonical markdown, give it the target job, ask for a proposed diff, then approve every change before publishing.
