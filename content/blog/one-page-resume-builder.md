The best resume workflow starts with a document you can actually read.

Most builders force you to choose between two bad shapes: a rigid form that hides the story, or a blank design canvas that makes every spacing decision feel permanent. Markdown keeps the source close to the words while Tiny CV keeps the output close to a real page.

## Markdown makes tailoring less fragile

A job-search resume changes constantly. You trim one bullet for a product role, add technical detail for an engineering role, and reframe the same project for a founder/operator conversation.

That work is easier when the source is plain text. You can see the structure, diff versions, ask an agent to make a targeted edit, and still review every word before publishing.

## A paper preview keeps the resume honest

One-page resumes fail when the editor pretends space is unlimited.

Tiny CV renders against fixed paper dimensions, so the tradeoffs are visible while you write. If a bullet pushes the page over the edge, the fix happens in the source instead of after a recruiter downloads a broken PDF.

## The public link should stay focused

A published resume is not a portfolio homepage, a template marketplace, or a builder UI. It should load quickly, look intentional, and keep the reader on the candidate.

That is why Tiny CV separates the editing experience from the public resume link. The editor can be powerful; the published page can stay quiet.

## The practical workflow

Use this pattern when you are updating a resume for a specific role:

1. Write the resume in markdown first.
2. Keep the headline under 80 characters.
3. Add a concise summary that matches the target role.
4. Give recent roles the strongest proof and collapse older work into Additional Experience.
5. Preview on paper before publishing or exporting.

The goal is not to make the resume fancy. The goal is to make the strongest one-page version easy to maintain.
